# PPT 评测模块实施计划（v1：自动评测全闭环 + 优雅降级渲染）

## 模块定位
在现有视频评测产品之上新增「PPT 评测」模块：上传 AI 生成的 .pptx（Kimi/Gamma/讯飞智文/WPS AI 等工具产出），按 **10 维三层体系**打分（本地指标 + 视觉大模型），结果落库并在看板出 PPT 子榜。复用现有架构模式（维度卡、一键测评、优雅降级、单机 data 目录），不破坏现有视频链路。

## PPT 维度体系（`spec_ppt_default_10`，锚定 0-10 分）

| 层 | 维度 | 打分通路 | 无渲染器时 |
|---|---|---|---|
| 内容层 | P01 内容完整性 / P02 逻辑连贯性 / P03 文本质量 / P04 信息真实性（AI幻觉检测） | LMM（读全文大纲文本，可选加渲染图） | ✅ 可评 |
| 设计层 | P05 排版质量 / P06 配色可读性 / P07 风格一致性 | LMM（看渲染后的幻灯片图） | ❌ 显示"需渲染器" |
| 语义层 | P08 主题符合度 / P09 受众与场景适配 | LMM（文本 + 可选图） | ✅ 可评 |
| 本地指标 | P10 结构规范度 | 纯 python-pptx 本地计算，零成本零依赖 | ✅ 可评 |

P10 本地指标（启发式，与视频侧 D03/D04 设计哲学对偶）：文字密度过载页占比、最小字号、字体种类数、文本框溢出风险估算、母版/版式一致性。每维三级行为锚点，门控类型沿用 技术/内容/语义 三分类。

## 核心改动

### 1. `app/core/ppt.py`（新文件，PPT 业务核心）
- `ppt_meta`/`extract_outline`：python-pptx 解析页数、每页标题+文本、字体/颜色集合
- `local_metrics`：P10 计算（含 note 说明构成）
- `detect_renderer()`：探测 PowerPoint COM（win32com，**用子进程隔离渲染**避免 COM 线程模型拖垮服务进程）→ LibreOffice headless 转 PDF + pypdfium2 出 PNG → 都没有返回 None
- `score_dim`：复用 `core/lmm.py` 的调用模式（维度锚点 prompt + 抽样页图 + 严格 JSON 返回）

### 2. 存储（`core/storage.py` 扩展，不碰现有表）
- 新表 `decks`（file_hash 去重、tool_tag、prompt_text、slide_count）与 `deck_scores`（镜像 scores 结构）；文件存 `data/decks/`
- 新函数：`add_deck / list_decks / delete_deck / get_deck_path / insert_deck_objective_score / deck_dashboard_data`
- 迁移安全：CREATE TABLE IF NOT EXISTS，现有 videos/scores/test_records 不动

### 3. 服务层（`server.py` 新路由）
`POST /api/deck/upload`、`GET /api/decks`、`DELETE /api/deck/{id}`、`GET /api/ppt-dimensions`（含 `needs_render` 角标）、`POST /api/deck/evaluate/{dim_id}` 与 `/api/deck/evaluate-all`（沿用"逐维失败不落库"哲学）、`GET /api/deck/{id}/slide/{n}.png`（预览图）、`GET /api/ppt/renderer`（渲染器探测结果）

### 4. 前端（`web/`）
导航新增「PPT 评测」页：上传卡（.pptx + 工具标识 + 生成 prompt）→ PPT 维度卡（本地/需渲染/需模型角标，交互复用视频维度卡）→ 一键测评 → 渲染预览网格（有渲染器时）→ 页内嵌 PPT 模型子榜。视觉风格复用现有卡片体系。

### 5. 依赖
`python-pptx`（纯 Python，进 requirements + lock + PyInstaller 包）；`pypdfium2`（仅 LibreOffice 渲染 PDF→PNG 用，importorskip 可选）；pywin32 若本机有则用、不做硬依赖。

### 6. 测试（`tests/test_ppt.py`，目标 +8 用例）
conftest 加 python-pptx 造 3 页测试文件的 fixture；覆盖：上传/去重/删除、P10 本地出分、无 LMM 时 evaluate-all 的降级行为、无渲染器时设计维度 note="NO_RENDERER" 不落库、看板聚合结构。

### 7. 验证与交付
门禁（pytest/ruff/mypy/node）→ 起服务用真实 pptx 走"上传→一键测评→子榜"全流程 → 重新打包 exe 部署桌面 → 更新主 README/`app/README`/HANDOFF（PPT 模块一节）→ 提交并推送 GitHub。

## 边界说明（v1 明确不做）
人工评分工作台 PPT 版（二期）、.ppt/.pdf/Keynote 格式、演讲备注与动画评测、多人对比。

## 风险与对策
- COM 渲染在服务进程内有线程模型陷阱 → 渲染一律走子进程脚本
- 文本溢出估算为启发式 → note 中明示构成，定位与 D03/D04 相同
- LibreOffice 转换慢 → 渲染加超时与页数上限
