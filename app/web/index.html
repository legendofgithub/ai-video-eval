PRODUCT BRIEF

AI 生成视频质量评测工作台

一套可离线运行、可打包分发的十维视频质量评测系统。用本地信号指标与视觉大模型双路打分，用人工 MOS 与专家仲裁做校准，最终产出可诊断、可复现、可比对的结构化报告。

01

产品定位与硬约束

这不是 SaaS，是一个人的评测工具。约束决定了架构的全部形状。

个人自用 不做多租户、不做账号体系。评测对象就是本地硬盘上的视频文件。
双击即用 PyInstaller 打成单 exe，系统托盘常驻，不要求用户装 Python。
零基础设施 SQLite 单文件 + 本地文件系统。没有 Redis、没有对象存储、没有任务队列。
可离线 前端零 CDN 依赖，图表全部手写 SVG。断网状态下界面照常渲染。

这套约束的直接后果：D03 / D04 两个时序维度必须脱离大模型——因为不能假设用户有可用的视觉 API，也不能为两个维度引入 GPU 依赖。这催生了下面的双路评测设计。

02

工程架构

四层单向依赖：前端 → 服务层 → 核心层 → 存储层。业务逻辑全部收在核心层。

storage.py 与 logger.py 同属核心层，图中未单列。服务层与核心层之间的边界是硬性的：任何 SQL、任何模型调用都不允许出现在 server.py 里。

双路评测：不是所有维度都该交给大模型

通路 A · 本地信号
D03 时序闪烁 / D04 运动平滑度

静态抽帧的致命问题：单张图片观测不到运动。早期版本把这两维也丢给视觉模型，模型自己就承认"缺乏连续帧，运动连贯性无法直接观测"。

  • D03：拉普拉斯边缘方差的时序变异系数 + 帧间差分变异系数，加权成闪烁指数，再指数映射到 0–10 分。
  • D04：Farneback 稠密光流求每帧运动幅值，取相邻帧差分的归一化 jerk 作为突变度。
零 API 成本 · 确定性可复现 · 结果不漂移
通路 B · 视觉大模型
D01 D02 D05 D06 D07 D08 D09 D10

语义与世界模型类问题本质上是"看懂画面内容"，这恰好多模态模型擅长。走 OpenAI 兼容协议，因此 GPT-4o / Gemini / DeepSeek 视觉 / 本地 Ollama 可无缝切换。

  • 均匀抽 8 帧送模型（可配置），逐维度独立提问，避免维度间相互污染。
  • 支持多次采样取均值，temperature 默认 0，降低打分抖动。
  • 模型失败不落库——宁可该维度为空，也不写入不可信分数。
API Key 只存浏览器会话，不写入磁盘、不进版本库

03

评测体系：三层金字塔

从"画面干不干净"到"世界讲不讲道理"，十维按认知层级分三层，低层缺陷不允许污染高层结论。

高层
世界模型D08 物理规律 · D09 人体结构 · D10 常识推理
中层
语义对齐D05 主体一致性 · D06 背景一致性 · D07 文本-视频对齐
底层
技术质量D01 成像质量 · D02 美学质量 · D03 时序闪烁 · D04 运动平滑度
为什么要分层？因为"画面糊"和"人穿墙"是两类完全不同的失败。前者是渲染管线问题，后者是模型对世界的理解错了。混在一起，报告就只能输出"这个视频 5.2 分"——对做模型的人毫无价值。
04

Benchmark 出题：按能力维度构造题目

出一套能用的题，先要回答"这个能力到底怎么被证伪"。下表逐项给出考察设计，以及本系统当前的真实覆盖状态。

能力维度题目怎么出对应维度覆盖
角色一致性 给同一角色的多段生成结果，考察跨帧、跨镜头的身份保持：发色、服饰、面部特征是否漂移。构造负样本时故意混入中段变脸的样本。 D05 主体一致性 已覆盖
物理合理性 设计必现的物理场景：球落地必须反弹、液体必须向下流、物体脱离支撑必须坠落。这类题的判据是客观的，不依赖审美。 D08 物理规律
D10 常识推理		 已覆盖
人体结构 专门出大幅度动作题（挥手、奔跑、转身），因为静态姿态下模型很少出错，错误集中在关节运动的中间帧。 D09 人体动作与结构 已覆盖
多镜头连贯 要求生成多镜头序列，考察切点是否合理、场景是否衔接、时空是否连续。 D06 背景一致性
D04 运动平滑度		 部分覆盖
运镜 指定明确的镜头语言（推、拉、摇、移、跟随），考察运动是否符合指令且轨迹平滑。 D04 运动平滑度 部分覆盖
口型对齐 给人物台词 + 音频，考察唇形与音素的同步关系。 — 未覆盖
文字渲染 在画面中指定需要正确渲染的文字（招牌、字幕、书页），考察字形正确性与稳定性。 — 未覆盖
音画关系 考察音效与画面事件是否对齐、环境音是否与场景匹配。 — 未覆盖
诚实标注：上表后半部分是刻意保留的。口型对齐、文字渲染、音画关系三项当前完全没有覆盖——系统不做音频轨解析，也没有 OCR 专项维度。多镜头连贯与运镜只是部分覆盖：D04 测的是运动流畅度，不等于"运镜语义是否正确"；系统也没有镜头切点检测，无法判断切镜本身是否合理。

把这四项标成绿色很容易，但那会让整张表失去意义。Benchmark 的价值不在于题多，在于每一道题的判据站得住。

出题之外：反例校准库

纯靠文字规则无法让标注员形成稳定判断。规范里要求建立反例校准库——把典型物理违规做成标准样例，标注员上岗前必须能稳定识别，连续三次一致性偏低就要重新校准。这是把主观评分推向可复现的关键一步。

05

评分维度与评分细则

每个维度都定义了三级行为锚点，而不是"好 / 中 / 差"这类无法执行的抽象描述。

维度2 分档（低锚点）5–6 分档（中锚点）9 分档（高锚点）
D01 成像质量明显噪点 / 模糊 / 压缩块基本清晰，偶有瑕疵通透清晰无伪影
D03 时序闪烁持续闪烁 / 画面跳动偶发微闪时序稳定无闪
D05 主体一致性主体外观频繁变化主体大体一致全程主体稳定
D08 物理规律明显违重力 / 碰撞 / 浮力偶有轻微违和符合物理规律
D09 人体结构骨骼 / 关节明显畸变轻微不自然人体结构合理

最容易出错的地方：技术失真 vs 物理常识错误

这是整套细则的核心难点。混淆两者会同时污染底层质量分与高层世界模型分，让一致性指标和最终报告一起失真。规范给出的判断句是：

「假如现实中用摄像机拍一段真实视频，会出现这个现象吗？」
  • 不会，原因是画面脏 / 抖 / 糊 / 闪 / 卡 / 色偏 → 技术失真，记 D01–D04
  • 不会，原因是物体行为违反物理或常识 → 物理常识错误，记 D08–D10
  • 不会，原因是和 prompt 不符 / 主体或背景变了 → 语义问题，记 D05–D07
现象容易误判为正确归类理由
人物边缘轻微闪烁物理错误技术失真 D03画面在抖，物理上人还站在那里
手臂穿过自己身体技术失真物理错误 D09骨骼结构不可能
背景建筑倒立悬浮技术失真物理错误 D08违反重力
运动有点卡顿物理错误技术失真 D04渲染不顺，物理上可解释
猫的颜色逐帧微变物理错误语义 D05不是物理违例，是主体性漂移
06

评价执行与结构化报告

从打分到出报告，中间有四道机制保证数据可信：门控、留痕、一致性校验、结构化导出。

1
质量门控

提交低分（≤4）时必须做二元初判：这是技术失真、物理常识错误，还是语义错位。选"物理常识错误"却没写说明的记录标记 is_valid=false，不参与统计。

2
结构化留痕

高层低分必须按固定格式记录，让报告能指出"哪里错了"而不只是"得了 4 分"。

D08 违反重力(悬浮不落) @ 00:02 ; 高
D09 反关节(左臂穿胸)   @ 00:05 ; 中
D10 因果错乱(先碎后落) @ 00:07 ; 高
3
一致性校验

同一视频至少两名标注员独立打分，系统计算 ICC(2,1) 与 Krippendorff's α 两个指标，低于阈值（ICC<0.6 / α<0.667）自动标红，触发标注对齐会。

这两个指标都曾在本项目中被写错过：ICC 漏了列效应项，α 用了非标准的自造公式。两者都已按标准定义重写，并用独立参考实现做过基准核对。

4
专家仲裁与导出

分差大于 3 分的争议样本自动送专家仲裁，仲裁分覆盖主观均值。最终导出 VBench 兼容 JSON，可直接接入外部对比流程。

报告长什么样

数据看板提供四张图：全样本质量轮廓雷达、MOS 分布直方图、模型 Leaderboard、世界模型子榜（D08–D10）。雷达图上客观分与人工分是两条独立曲线——混在一条线上会让人误以为机器分和人的判断是一回事。

07

已知边界

这套系统当前做不到什么，以及为什么。

  • 不做音频分析。口型对齐、音画同步、配音质量全部不在覆盖范围内。
  • 不做 OCR。画面内文字渲染的正确性没有专项维度，只能由 D01 间接反映清晰度。
  • 不做镜头结构分析。没有镜头切点检测，多镜头题只能评"连不连贯"，评不了"切得对不对"。
  • 本地信号指标是启发式的。D03 / D04 的映射公式不是学术标准指标，它的价值在于确定性和可复现，不在于与人类感知的绝对对齐。
  • 大模型打分不是 ground truth。它是可复现的近似标注，人工 MOS 与专家仲裁才是校准基准。
  • 一键测评与逐维评测并存。「一键完成测评」一次跑完十维（D03/D04 本地、8 维连续调用视觉模型，约 1–2 分钟），失败维度跳过且不落库；逐维度评测仍保留，用于单维复核与成本控制。归档快照存入「测评档案」，独立于后续重测。
